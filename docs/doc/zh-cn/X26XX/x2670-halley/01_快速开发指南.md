# SDK 简介

## 工程整体结构

X26xx Halley配套的软件开发平台是君正开发的一套linux系统的发布、开发平台，平台的编译系统可支持c文件、cpp文件。同时可支持静态库、动态库以及可执行文件的编译生成。本软件开发平台还能够快速方便的集成、添加第三方应用和库文件。工程支持整体编译、模块的单独编译以及选择性编译。本软件开发平台的工程目录如图2-1所示。

| 工程结构        |                        |
| ----------- | ---------------------- |
| build       | 整个工程的编译规则和说明文档         |
| buildroot   | buildroot源码，提供最基础的文件系统 |
| development | 开发中的软件库                |
| device      | 板级配置信息                 |
| docs        | 文档说明及SDK用户手册           |
| external    | 第三方软件包                 |
| frameworks  | 中间件软件库                 |
| kernel      | kernel源码               |
| packages    | 应用程序                   |
| prebuilts   | 编译工具链                  |
| tools       | ota升级工具                |
| u-boot      | uboot源码                |

# SDK 编译

## 整体编译

本节主要介绍快速对SDK工程进行整体编译的方法，编译步骤具体如下：

1、设置环境变量

在工程目录下执行命令： 

```c
$ source build/envsetup.sh
```

1. 选择device

在工程目录下执行命令： 

```c
$ lunch 
```

命令执行结束后会显示不同的配置方案，请根据开发板的配置输入编号进行选择，例如X2660 halley.v10。同时需要注意区分开发板的存储类型，如nand、nor和msc。关于lunch配置中的各选项的说明可参考表２的解读。如需要用到配置选择其对应编号即可，本文档中以X2660halley.v10_nand_4.4.94-eng 配置进行演示。

|                                   |                                                      |
| --------------------------------- | ---------------------------------------------------- |
| 配置选项名称                      | 配置说明                                             |
| x2600halley7.v10_msc_6.6-eng      | 适用于编译X2600开发板的kernel 6.6版本msc启动         |
| x2600halley7.v10_msc_6.6_ota-eng  | 适用于编译X2600开发板的kernel 6.6版本msc版本OTA升级  |
| x2600halley7.v10_nand_6.6-eng     | 适用于编译X2600开发板的kernel 6.6版本nand启动        |
| x2600halley7.v10_nand_6.6_ota-eng | 适用于编译X2600开发板的kernel 6.6版本nand版本OTA升级 |
| x2600halley7.v10_nor_6.6-eng      | 适用于编译X2600开发板的kernel 6.6版本nor启动         |
| x2670hare.v10_nand_6.6-eng        | 适用于编译X2670开发板的kernel 6.6版本nand启动        |
| x2670hare.v10_nand_6.6_ota-eng    | 适用于编译X2670开发板的kernel 6.6版本nor版本OTA升级  |
| x2670hare.v10_nor_6.6-eng         | 适用于编译X2670开发板的kernel 6.6版本nor启动         |

1. 工程编译

在工程目录下执行make或make MAKE_JLEVEL=8或make -j8（多线程编译)

```c
$ make -j8 
```

注意：由于机器性能的不同编译时长也会有差异，通常会在2小时以上。

至此，工程的整体编译工作已完成。编译结果的输出具体如下：

①　工程目录/out/product/x2660halley.v10_nand_4.4.94-eng/image，生成kernel、system.ubifs、uboot镜像。

②　工程目录/out/product/x2660halley.v10_nand_4.4.94-eng/obj是buildroot、kernel、uboot、packages等编译过程中的输出的中间文件。

1. 工程clean

```c
$ make clean 
```

## 单独编译

本节主要介绍如何对uboot、kernel、buildroot和模块的单独编译，最后还将介绍如何打包文件系统镜像。在进行模块单独编译前需要进行环境变量设置和device的选择，具体操作请参考2.1中的相关描述，如当前终端已经设置无须重新设置。（*需要注意的是单独编译的前提条件是工程已进行了整体编译*）

### 编译uboot

1、清除uboot编译结果的方法，在工程目录下执行命令：

```c
$ make uboot-clean 
```

2、编译uboot的方法，在工程目录下执行命令：

```c
$ make uboot 
```

### 编译kernel

1. 清除kernel编译结果的方法，在工程目录下执行命令：

```c
$ make kernel-clean 
```

1. 配置kernel的方法，在工程目录下执行命令：

```c
$ make kernel-menuconfig 
```

3、编译kernel的方法，在工程目录下执行命令：

```c
$ make kernel -j8 
```

### 编译buildroot

1、清除buildroot编译中间文件的方法，在工程目录下执行命令：
```c
$ make buildroot-clean 
$ make buildroot-distclean 
```

2、配置buildroot的方法，在工程目录下执行命令：

```c
$ make buildroot-menuconfig 
```

3、编译buildroot的方法，在工程目录下执行命令： 

```c
$ make buildroot -j8 
```

4、局部修改buildroot后编译buildroot的方法，在工程目录下执行命令

```c
$ make buildroot-rebuild 
```

1. 在对一些第三方库或者是内核工具软件如，opencv和i2c-tools_4.1做出修改后可以通过执行buildroot内置的命令进行单独编译。

```c
$ make buildroot-opencv-rebuild
$ make buildroot-i2c-tools-rebuild 
```

buildroot工程所包含的第三方软件位于buildroot/packages目录下，编译输出位于/out/product/x26xx_halley/obj/buildroot-intermediate/build。

1. 关于buildroot其它命令的支持可以通过help选项进行查询，在工程目录下执行命令：

```c
$ make buildroot-help 
```

### 编译模块

本工程支持对单个模块的编译及对单个模块的clean操作。工程的编译系统初始化后，存在两套单模块的编译方法，一种是通用的模块编译方法mma命令，另外一种是直接在工程目录下使用make命令。在单独编译模块之前，需要确保当前终端的环境变量已设置，具体请参考2.1小节中的相关描述。

#### mma命令单独编译模块

mma命令为通用单模块编译方法，不区分此模块为host端还是target端。此命令的具体使用方法为：

1、进入到所要编译模块目录下，此模块目录下含有Build.mk文件。

2、执行mma命令，此模块以及此模块所依赖的模块都会被编译。

#### Target端模块编译

Tartget端模块编译是在工程目录下进行的，命令格式为：

```c
$ make $(LOCAL_MODULE) 
```

命令使用示例，以工程目录 /packages/example/App/v4l2-h264dec模块为例，该模块在其目录下的Build.mk文件中LOCAL_MODULE赋值为：v4l2-h264dec。单独编译模块只需要在工程目录下执行命令：

```c
$ make v4l2-h264dec
```

编译后的可执行文件最终将被直接安装到文件系统的相应路径下，可根据编译后最终的安装路径找到相应的可执行文件。

#### Target端模块clean

Tartget端模块clean可在工程目录下进行，命令格式为：

```c
$ make $(LOCAL_MODULE)-clean 
```

命令使用示例，以工程目录 /packages/example/App/v4l2-h264dec模块为例，该模块在其目录下的Build.mk文件中LOCAL_MODULE赋值为：v4l2-h264dec。单独clean概模块只需要在工程目录下执行命令：

```c
$ make v4l2-h264dec-clean
```

### 编译文件系统镜像

　　　单独编译文件系统镜像的方法为，在工程目录下执行命令：

```c
　$ make systemimage 
```

命令执行结束后，会在工程目录/out/product/X26xx-Halley/image下重新生成system的镜像。

### 打包文件系统镜像

打包文件系统镜像，将编译后输出的文件打包成最终的文件系统镜像，用于烧录到开发板。打包文件系统镜像需要在工程目录下执行命令：

```c
$ make post-image 
```

最终的文件系统镜像输出在工程目录/out/product/X26xx-Halley/image目录下。

## 编译kernel出现问题

```c
/home/xxx/X26xx/kernel/kernel-4.4.94 is not clean, please run 'make mrproper'

in the '/home/xxxX26xx/kernel/kernel-4.4.94' directory.

/home/xxx/X26xx/kernel/kernel-4.4.94/Makefile:1003: recipe for target 'prepare3' failed

make[2]: \*\*\* [prepare3] Error 1

make[2]: Leaving directory '/home/xxx/X26xx/out/product/X26xxhalley.v10_nand_4.4.94-eng/obj/kernel-intermediate'

Makefile:150: recipe for target 'sub-make' failed

make[1]: \*\*\* [sub-make] Error 2
```

出现上述现象通常是因为在kernel目录下执行了　make menuconfig进行了配置，然后到工程目录下执行编译命令造成的。这个时候的解决办法:

1. 到kernel目录下执行命令

```c
$　make distclean
```

1. 回到工程顶层目录执行lunch选择板级后，并执行命令编译内核

```c
$　make kernel -j8
```

提示：本SDK所有的编译配置都可以在工程顶层目录进行编译配置，具体参考本文档相关内容，不建议进入到某个目录下单独进行配置。
